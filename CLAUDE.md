# Salida Weather Dashboard

A static HTML weather + webcam dashboard for a wall-mounted display in Salida, CO. Hosted on GitHub Pages, loaded by Chromium in kiosk mode on a Raspberry Pi Zero 2 W driving a cheap 10" HDMI monitor.

Goal: glance up, see current conditions, look outside via the Tenderfoot Mountain PTZ cam, see what the next 10 days look like. No interactivity, no settings, no auth.

## Hardware target

- **Pi:** Raspberry Pi Zero 2 W (quad-core ARM Cortex-A53 @ 1GHz, 512MB RAM)
- **OS:** Raspberry Pi OS Lite (Bookworm, 32-bit, May 2025 release)
- **Browser:** Chromium in kiosk mode (fullscreen, no UI chrome)
- **Display:** Loncevon 10.1" HDMI monitor, display-only (no touch)
  - Native resolution: either **1024×600** or **1280×800** — TBD, confirm on first run
- **Network:** 2.4GHz WiFi

## Performance constraints

The Pi Zero 2 W is modest. Build accordingly:

- **No build step.** Plain HTML/CSS/JS. No transpilation, no bundling, no `package.json`. Easier deploy, easier debug, easier iterate.
- **No frameworks.** Vanilla JS only. React/Vue/etc. are wasteful here.
- **No CDN font loading** if avoidable. System fonts are fine. Self-host any webfont if absolutely required.
- **Lightweight icons.** Inline SVG preferred. If using an icon library, pick something small (e.g., a few Tabler Icons inlined, not the full font).
- **No animations** beyond basic fades. No render loops.
- **Static layout.** No drag, resize, or scroll.
- **The page lives on screen for weeks.** No memory leaks. Be careful with detached DOM nodes, growing arrays, and event listener accumulation.

## The RSS feed

Mountain Mail runs on BLOX CMS. The RSS URL follows BLOX's search-feed convention:

```
https://www.themountainmail.com/search/?q=&t=article&l=20&s=start_time&sd=desc&f=rss
```

Parameters: `q=` empty query (required, even when empty), `t=article` only articles, `l=20` twenty items, `s=start_time&sd=desc` newest first, `f=rss` output format.

## Workflow (`.github/workflows/headlines.yml`)

```yaml
name: Update headlines
on:
  schedule:
    - cron: '0 */3 * * *'   # every 3 hours UTC
  workflow_dispatch:

permissions:
  contents: write

jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Fetch RSS
        run: |
          curl --fail --max-time 30 \
               -A "KitchenDash/1.0 (+https://github.com/conspiculus/kitchendash)" \
               "https://www.themountainmail.com/search/?q=&t=article&l=20&s=start_time&sd=desc&f=rss" \
               -o headlines.xml
      - name: Commit if changed
        run: |
          git config user.name  "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add headlines.xml
          git diff --staged --quiet || git commit -m "Update headlines $(date -u +'%Y-%m-%d %H:%M UTC')"
          git push
```

## JS

```js
const RSS_PATH = 'headlines.xml';
const REFRESH_MS = 15 * 60 * 1000;   // dashboard re-fetches every 15 min

const escapeHtml = s => s.replace(/[&<>"']/g, c => ({
  '&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'
}[c]));

async function loadHeadlines() {
  try {
    const res = await fetch(`${RSS_PATH}?t=${Date.now()}`);  // cache-bust
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const xml = await res.text();
    const items = [...new DOMParser().parseFromString(xml, 'text/xml').querySelectorAll('item')]
      .map(item => ({
        title: item.querySelector('title').textContent,
        link:  item.querySelector('link').textContent,
      }));
    renderTicker(items);
  } catch (err) {
    console.error('Headline fetch failed:', err);
    // leave previous ticker content in place
  }
}

function renderTicker(items) {
  const track = document.getElementById('ticker-track');
  const html = items
    .map(it => `<span class="news-ticker-item">${escapeHtml(it.title)}</span>`)
    .join('');
  track.innerHTML = html + html;   // duplicate for seamless loop
}

loadHeadlines();
setInterval(loadHeadlines, REFRESH_MS);
```

## Setup sequence

1. Add `.github/workflows/headlines.yml`, commit, push.
2. Repo Settings  Actions  General  set "Workflow permissions" to **Read and write permissions**. (Default is read-only, which makes the commit step fail with 403.)
3. Actions tab  "Update headlines"  "Run workflow" to trigger manually rather than waiting for the next 3-hour boundary.
4. Wait ~15-30s for completion. `headlines.xml` appears in the repo root.
5. Add the HTML/CSS/JS to the dashboard, commit, push.
6. Reload the dashboard on the Pi.

## Pi performance notes

GPU compositing is disabled on the Pi Zero 2 W (see main project summary). Implications for the ticker:

- Animation must be CSS `transform: translateX()`, never JS-driven position changes. JS-driven animation causes layout thrashing and will peg the CPU.
- `will-change: transform` on `.news-ticker-track` is essential. Without it, Chromium repaints the entire dashboard every frame instead of just the ticker layer.
- A single-element marquee at 1024x600 is well within the CPU-only budget. Expect one core at roughly 15-25% during scroll. If higher, fall back to a step-based ticker (jump one headline at a time on a timer).

## Gotchas encountered

1. **Direct browser fetch of RSS fails with CORS.** Newspaper RSS feeds don't send `Access-Control-Allow-Origin` headers, since RSS readers historically fetch server-side. Hence the same-origin mirror approach.

2. **rss2json.com gets blocked by Mountain Mail's server.** The same RSS URL that returns valid XML in a normal browser returns HTML (or a bot-challenge page) to rss2json's IP range. rss2json reports "Feed could not be parsed."

3. **allorigins.win is unreliable.** Intermittent 522 timeouts. Free public CORS proxies in general have the wrong durability profile for an unattended kitchen display.

4. **BLOX RSS URL needs `q=` even when empty.** The minimal working URL is `/search/?q=&t=article&f=rss`. Without `q=`, the search endpoint returns HTML instead of RSS, and proxies will report a parsing error that looks like the feed is broken.

5. **GitHub Pages caches aggressively.** The dashboard JS must cache-bust `headlines.xml` with `?t=${Date.now()}` or it will see stale content for hours after a workflow run.

6. **Default GitHub Actions permissions are read-only.** Must be changed to "Read and write permissions" in repo settings, otherwise the commit step in the workflow fails with 403.- **Location:** Salida, CO — `lat=38.5366, lng=-105.9923`, elevation 7,083 ft

- **Failure handling:** Cache last successful response in memory; if a refresh fails, keep showing previous data and the last-updated timestamp.

## Deployment

- **GitHub Pages** from the `main` branch (or `/docs` folder, whichever is configured)
- `git push` → live within ~1 minute
- Pi's Chromium will be pointed at the deployed URL
- Page handles its own refresh on timers — no full page reloads needed in normal operation

## Resilience requirements

- Both data sources can and will fail. Neither failure should disrupt the dashboard.
- No data should ever disappear from the screen because of a failed fetch — always keep showing the last good value.
- The Pi runs for weeks between reboots. No accumulating event listeners, no growing arrays, no memory leaks. Validate this by checking `performance.memory` if possible during dev.

## Out of scope (v1)

- Touch interaction
- Settings UI
- Multiple locations or webcams
- Service worker / offline support (the page can't function offline — both data sources require internet)

- Hourly forecast detail

## Architecture

The dashboard is static and served from GitHub Pages, so it cannot fetch external RSS feeds directly (CORS). A scheduled GitHub Actions workflow mirrors the RSS feed into the repo, where it becomes same-origin to the dashboard:

```
